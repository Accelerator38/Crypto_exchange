# V8 Clean: фиксация данных отдельно для каждого origin

В сентябрьском контракте manifest должен был появиться до конца **всего** outer
interval. Для последнего трёхдневного окна это невозможно: полные данные
появляются не раньше его окончания, которое совпадает с концом interval.
Поэтому последнее сентябрьское окно осталось инженерной диагностикой.
Сентябрьские исходники, контракты и результаты не меняются.

`prospective_manifest_v2.py` вводит правило для **будущего** зарегистрированного
исследования. В его `data_commitment` должны быть объявлены:

```json
{
  "manifest_version": 2,
  "origin_snapshot_commit_rule": "after_origin_complete_before_evaluation",
  "origin_commit_deadline_hours": 72
}
```

Для каждого origin момент фиксации должен находиться в интервале
`[origin_end, origin_end + 72 часа)`. Правило одинаково для первого и последнего
окна, поэтому последнее можно честно зафиксировать после окончания всего
outer interval. Если данные опоздали, origin не подменяется и не оценивается
по этому протоколу. Поле `created_at_utc` берётся из текущих UTC-часов после
проверки данных, непосредственно перед записью manifest.

Manifest V2 дополнительно проверяет:

- точную четырёхчасовую сетку полного universe, покрытие обучающей истории
  и окончание снимка **ровно** на границе origin, без будущих свечей;
- конечные и согласованные OHLCV, положительные цены и неотрицательный объём;
- SHA256 и размер каждого Parquet, неизменность старых файлов при добавлении
  новых, SHA256 предыдущего manifest и хронологию цепочки;
- совпадение сохранённого контракта с переданным в память, срок фиксации,
  schema V2 и все отключённые trading/runtime/network permissions.

Перед расчётом PnL `reserve_origin_evaluation` повторно проверяет manifest
и данные, затем эксклюзивно записывает маркер начала. Повторная попытка с тем
же маркером или существующим результатом отклоняется. V1 manifest не может
быть принят как V2 evidence.

Это механизм целостности локального расчёта, а не доказательство того, что
человек до фиксации не видел рыночные свечи. Для нового prospective теста
потребуется заранее зарегистрированный контракт и внешний по отношению к
результатам timestamp/hash реестра; оценщик должен использовать V2 manifest
и одноразовый маркер. Публикация будущего Git commit с зафиксированным
контрактом даст проверяемую временную границу. Нельзя использовать V2 для
переклассификации сентябрьской диагностики.

Новый 30-дневный эксперимент со старым GA пока не зарегистрирован: GA закончил
сентябрь с отрицательной доходностью относительно NoTrade. Следующее решение
о кандидате требует отдельной гипотезы, фиксированных параметров и нового
периода, не использованного для её подбора. Никакой сети, collector, paper/live
или торгового runtime этот этап не запускал.

Проверка: `tests/test_genetic_primus_prospective_manifest_v2.py`, пять
детерминированных локальных сценариев, запущенных напрямую через проектный
Python без pytest.
