# Технический аудит — 2026-07-15

## Итог

Проект технически способен прогнать player-only контур от Retrodate до
исполнений. Полный `singleton(ResearchValidatorAgent)` прошёл offline promotion,
но это разрешает только Bitget demo/paper, а не торговлю реальными деньгами.
`multi` promotion не прошёл. Live credentials проверены read-only; на live
market data запущен `paper_live_feed` canary через `FakeExchange`, поэтому
биржевые ордера он отправить не может. Отдельно продолжает работать read-only
сборщик carry-flow с `orders_enabled=false`.
Последний старый live-status относится к 2026-06-27: режим Flash, 0 закрытых
реальных сделок и 0 открытых позиций; status позднее был помечен stale.

## Исправленные критичные расхождения

- Launcher имел три режима, а Bitget live принудительно использовал Policy V1.
  Теперь публичный контракт содержит только `multi` и `singleton`.
- Strategist мог выбирать ensemble по player-метрикам и подмешивать agent-
  метрики. Новый selector читает только один ключ `player|regime`.
- Shadow текущего бара обновлял общую память до выбора и создавал look-ahead.
  Теперь выбор завершается до shadow-исполнений текущего бара.
- Active path содержал Flash, Genetics overlay, fallback, soft allocator и
  несколько admission-слоёв. Player-only путь обходит их целиком.
- Старый snapshot мог загрязнить новую память совпадающими именами agents.
  Введён отдельный snapshot и обязательная метка runtime-контракта.
- Preflight принимал старые Panteon3/Policy доказательства. Теперь требуются
  свежие retro и canary артефакты `pantheon_players_v1`.
- Закрытие раньше записывалось в режим бара выхода, а не входа. Эффективность
  теперь относится к `player × entry regime`.
- Full-market стратегия вызывалась отдельно для каждого символа, хотя один
  вызов уже обрабатывал весь рынок. Теперь она вызывается один раз на бар.
- Синхронизация позиции перезаписывала исходный `opened_bar`, а смена лидера
  могла принудительно закрыть позицию. Исходный возраст сохраняется; смена
  откладывается до закрытия владельцем, а новые открытия блокируются через
  `manage_only`.
- Реальный player-only путь больше не пересчитывает стратегию вторым холодным
  экземпляром: он получает свежие исполненные shadow-сигналы выбранного игрока.
- Режимный рейтинг дополнен глобальным recency-рейтингом игрока, чтобы краткая
  локальная удача не продвигала глобально убыточную стратегию.
- Добавлен отдельный `demo_futures`: он принимает только `BITGET_DEMO_*`,
  добавляет обязательный `paptrading: 1`, использует отдельный snapshot и не
  может откатиться к live-ключам. Read-only probe гарантирует `orders_sent=0`.
- Snapshot памяти теперь изолирован по режимам: paper, demo и live не могут
  незаметно использовать память друг друга.
- Preflight теперь находит именованные `PlayerEfficiency*` result roots, но
  фактический live по-прежнему fail-closed без завершённого canary-артефакта.
- `paper_live_feed` bridge больше не получает authenticated credentials: он
  использует только public futures market data, `FakeExchange` и отключённый
  v1 order cycle. Устаревшее предупреждение «реальные деньги» заменено точной
  маркировкой `MARKET DATA ONLY`.
- Player-only dashboards больше не переименовывают стратегии в agents и не
  показывают неактивные Flash/Agent-панели.

## Открытые риски

### P0 — блокируют live

- Безопасный `paper_live_feed` canary нового runtime-контракта запущен, но ещё
  не завершил требуемую выборку закрытых сделок и потому не является promotion-
  доказательством для live.
- В существующем `.env.local` заданы только live Bitget credentials, но нет
  отдельных `BITGET_DEMO_*`; поэтому штатный launcher не использует live-ключи
  как fallback и fail-closed возвращает `credentials_missing`.
- Live dry-run принимает прошедший offline singleton, но останавливается на
  `canary_missing`; этот gate намеренно не обходился.
- `multi` остаётся отрицательным и не допускается ни в demo, ни в live до новой
  гипотезы модели и повторного заранее зафиксированного gate.

### P1 — модели и данные

- `GeneticsCore` не регистрируется без явного `PANTEON_V2_GENETICS_CORE_GENOME`.
  Сохранённые геномы обучены на MEXC и не имеют Bitget promotion-доказательства;
  автоматически подставлять один из них небезопасно. Явный singleton с таким
  именем завершится ошибкой вместо молчаливого fallback.
- Первый временной сегмент прошедшего singleton отрицателен (`-30.0964 USD`),
  поэтому live-стабильность ещё должна быть подтверждена demo canary.
- Shadow-память начинает с нуля; до достаточной выборки `multi` корректно стоит
  в `NoTrade`, поэтому нужен длительный paper warm-up.
- Исторический OHLCV набор целостен, но отдельный read-only carry-flow/funding/OI
  tape ещё накапливается и не является основанием для live до проверки качества.

### P2 — долг проекта

- `main_loop.py`, `startup.py` и retro runner остаются крупными: исторические
  Flash/Policy функции сохранены для воспроизводимости старых тестов, но
  недостижимы из launcher player-only. Следующий рефакторинг — физически вынести
  legacy runtime в `legacy/` после стабилизации нового canary.
- В проекте раньше не было воспроизводимого списка зависимостей и pytest-
  конфигурации; добавлены `requirements.txt` и `pyproject.toml`.
- Старые snapshots сохранены только как неактивная история; новый launcher их
  не читает.

## Уборка

Удалены кэши, устаревшие логи, сырые sweep-результаты, старые ветки, Flash/
Policy/Panteon3 отчёты, MEXC runtime-результаты и тяжёлые trace-файлы обучения.
Сохранены исходники, Retrodate, текущий Bitget collector, лучшие геномы и
компактные validation-артефакты. После удаления ещё 11 устаревших/незавершённых
player-retro прогонов освобождено дополнительно 3.067 ГиБ. Ветки: только
`main` и `origin/main`.
