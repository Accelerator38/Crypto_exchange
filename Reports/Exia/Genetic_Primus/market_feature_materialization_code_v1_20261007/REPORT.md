# Пошаговая materialization признаков: проверка кода

Дата: 2026-10-07. Статус: код проверен; сценарий доступности данных не выбран, materialization не запускалась.

## Реализовано

- Чистый планировщик обработки только ранее закреплённых исторических источников, без открытия новых sealed данных.
- Обработка одного parquet-файла за команду с передачей состояния EMA и короткого OHLCV-хвоста через локальный checkpoint.
- Проверка идентичности источников до и после чтения, связности checkpoints и hashes производных файлов; отказ от повторного использования частично записанного шага.
- Снимки признаков на причинном as-of и сохранение прежней сетки кандидатов с шагом 18 баров, без расширения числа возможностей.
- Отдельные команды подготовки, обработки файла, завершения и проверки. Обучение и labels не включены.

Checkpoint при будущей materialization будет содержать исторические цены последних 13 баров каждого символа и состояние EMA. Это машинный локальный артефакт; цены не выводятся в чат. Backend может декодировать более поздние строки внутри batch; Python-состояние и выходные признаки ограничиваются выбранным cutoff. Это не доказательство исходного времени доставки или исходной версии данных биржи.

## Выполненные проверки

1. `py_compile` только нового чистого helper: успешно.
2. Минимальный прямой вызов `plan` без выбранного сценария: materialization и fit запрещены.
3. `--check-code`: успешно; эквивалентность цельной и разделённой обработки проверена на вымышленных данных с сериализацией и восстановлением checkpoint.
4. `--verify-code`: успешно; сохранённые результат и receipt воспроизводятся.

Фактические parquet-чтения: **0**. Labels: **не материализованы**. Fit: **0**. Сеть, runtime и ордера не запускались; все safety-разрешения остаются false.

## Следующий шаг и ограничения

После явного выбора пользователем лага 0 или 1 можно выполнить features-only materialization: подготовка, девять последовательных файловых шагов, завершение и проверка receipt. Без выбранного лага pipeline остаётся закрытым.

После этого отдельно потребуются зарегистрированная задержка исполнения, причинные labels, согласованное net-accounting и интеграция полного переобучения. Текущий этап не даёт оценки доходности, превосходства над NoTrade или допуска к реальным торгам; исторический интервал не становится prospective.
